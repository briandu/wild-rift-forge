01 — THE RULES
Mirror layout, not content
A skeleton block sits at the exact height, width and radius of the thing replacing it. If content shifts when it lands, the skeleton was wrong. Text lines get percentage widths so they read as prose, never full-width bars.
One sweep, one speed
Every skeleton on the page runs the same 1.4s sweep. Stagger by 60ms per row to a 300ms cap, so a long table reads as one wave instead of forty independent blinks.
Under 300ms, show nothing
A skeleton that flashes for 120ms is worse than no skeleton. Delay the skeleton by 300ms; if data arrives first it never paints. Once shown, hold it for at least 400ms so it does not strobe.
02 — THE PRIMITIVE
One block, three depths
Depth tracks the visual weight of what is missing. A champion portrait is a level 1 block; the body copy under it is level 3. Mixing depths is what keeps a skeleton from looking like a grey rectangle farm.

04 — WHAT A SKELETON CANNOT SAY
Four states that need their own treatment
PENDING ACTION
The user pressed something. Lock the control, keep its width, swap the label for a spinner. Never skeleton a button — the user knows what it said.

Adding
STALE WHILE REFRESHING
Data exists but is being replaced. Keep the old content readable at full opacity, run a hairline creep across the top of the container. Replacing readable data with skeletons is a downgrade.
